# Вики qa-notes: как здесь работать

Это вики заметок. Из папки `notes/` скрипт `build.py` собирает сайт в `site/`.

## Где лежат заметки

- Заметка — файл `notes/<раздел>/<имя>.md`, например `notes/databases/redis.md`.
- Имена папок и файлов — латиницей через дефис. Читатель их не видит.
- Название для читателя — по-русски: у заметки поле `title`, у раздела — файл `<раздел>/_section.md`:
  ```markdown
  ---
  title: Базы данных
  ---
  ```
- Нужного раздела нет — создай папку и в ней `_section.md`. Перед созданием заметки посмотри `INDEX.md`:
  вдруг она или подходящий раздел уже есть.
- `INDEX.md` — каталог всех заметок: раздел, имя, title, summary, какие разделы внутри. Его пишет `build.py`
  при сборке — читай, но не правь.
- `site/` не трогай: его собирает `build.py`.
- `about.md` — страница об авторе. Не трогай её, даже когда «приводишь заметки в порядок».

## Сырой текст → заметки

Пользователь присылает сырой текст (конспект, переписку, вывод команды) и не участвует в разборе. Делай сама:

1. Собери (так каталог свежий) и прочитай `INDEX.md` — он в корне папки, рядом с `build.py`, не в `notes/`.
   Там все заметки и о чём они.
2. Раздели текст на темы: одна тема — одна заметка. Факт про одну тему не клади в заметку другой
   (consumer group Kafka — не в Redis).
3. Для каждой темы:
   - заметка про эту тему уже есть — `read_file` её и допиши `edit_file` только то, чего в ней ещё нет:
     пункт уже есть другими словами — не добавляй; существующий текст не переписывай;
   - нет — создай новую по образцу ниже, в подходящем разделе или в новом;
   - две заметки про одно и то же — перенеси всё в одну, вторую удали, ссылки `[[старое-имя]]` замени на новое.
4. Свяжи заметки через «См. также», только если темы правда связаны (Kafka и RabbitMQ — да, Redis и XML — нет),
   и в обе стороны.
5. Обязательно, до ответа: собери (`run` с командой из «Команды») и исправь предупреждения.
6. В ответе — список: что создано, что дополнено, что объединено.

Не выдумывай: в заметку идёт только то, что есть в тексте, — без своих чисел, проверок и ссылок.
Настройки, конфиги, команды из текста — в раздел «Настройки» как есть, в блоке кода.

## Образец заметки

~~~markdown
---
title: Redis — кэш и очереди
status: draft
summary: одна строка: что это и зачем
updated: 2026-10-26
---

## Что это

Коротко: что за технология и где применяется.

## Настройки

```
maxmemory 2gb
maxmemory-policy allkeys-lru
```

## Как тестировать

### Группа проверок
- [ ] пункт чек-листа

## Ссылки

- [Документация](https://redis.io/docs/)

## См. также

[[postgresql]]
~~~

Разделы `##` называй по содержанию, по-русски: «Виды тестов», «Узкие места», «Команды».
«Что это» есть всегда; «Настройки» — только конфиги и параметры, «Как тестировать» — только чек-лист `- [ ]`.
Не клади в раздел то, что ему не подходит, — заведи свой. Термины можно латиницей (Load, Soak, CPU),
заголовки — нет: «Узкие места», а не «Bottleneck Analysis». Таблицы Markdown можно. `status`: `draft` — черновик, `done` — готово, `todo` — только тема.
`updated` — сегодняшняя дата.

## Связи

- Ссылка на заметку — `[[имя-файла]]` без `.md`. Ставь только на заметки, которые есть в `notes/`.
- Связанные заметки перечисляй в разделе «См. также».

## Команды

- «собери» — `run` с командой `.venv/bin/python build.py` (на Windows `.venv\Scripts\python build.py`).
  Если в выводе есть строки `предупреждение:` — исправь заметки и собери снова.
  `site/<имя>.html: вёрстка: …` — в заметке `<имя>.md` сломанный HTML: пиши чистым Markdown, без тегов.
- «проверь вики» — собери, прочитай `INDEX.md` и найди: дубли (две заметки про одно), заметки не в том разделе,
  заметки «Без связей», которым правда есть с чем связаться. Исправь, собери снова, в ответе — что сделала.
- «опубликуй» — сначала собери без предупреждений, потом `git_commit` с сообщением о том, что изменилось,
  потом `run` с командой `git push`. Сайт выложит GitHub сам.
